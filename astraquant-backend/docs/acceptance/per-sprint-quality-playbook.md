# Per-Sprint Quality Playbook

本文档用于指导 AstraQuant 后续验收推进。核心目标不是重构系统，而是让每个 Sprint 的能力在平台中真实可用、可联调、可测试、可追溯。

## 1. 基本原则

1. 逐 Sprint 完善，不做无必要重构。
2. 保留当前 20 个 Sprint 已经形成的系统演进结果。
3. 原始 Sprint 文档作为需求来源，当前实现作为验收对象。
4. 每个 Sprint 都输出明确的验收口径，再补测试和修缺口。
5. 质量由测试工程师视角保证，开发只负责让验收项可执行、可观测、可回归。
6. 所有验收必须服务于平台真实使用，而不是只证明函数可运行。

## 2. 每个 Sprint 的固定验收包

每个 Sprint 都必须沉淀以下内容：

```text
1. 原始设计摘要
2. 当前实现清单
3. 设计与实现差异
4. 保留差异与修复差异
5. 后端 API 对接说明
6. 前端页面/交互对接说明
7. 数据库与事件验收点
8. 权限与安全验收点
9. 测试用例清单
10. 自动化测试/验收脚本
11. 问题清单与修复记录
12. 验收结论
```

## 3. 质量保证角色分工

### 产品/业务验收

- 验证 Sprint 目标是否满足业务闭环。
- 确认用户操作路径是否合理。
- 确认页面信息是否能支撑业务决策。

### 开发工程师

- 保证接口、数据、事件、权限和服务启动能力完整。
- 对验收缺口做最小范围修复。
- 不因为验收而引入跨 Sprint 大规模重构。

### 测试工程师

- 负责制定和执行测试用例。
- 覆盖 happy path、异常路径、权限边界、数据一致性和回归影响。
- 对每个 Sprint 给出可重复执行的验收结论。

## 4. 验收测试分层

### L1 单元测试

验证纯领域逻辑：

- 状态机
- 规则引擎
- 参数校验
- 评分计算
- 权限判断
- 风控判断

### L2 服务 API 测试

验证单服务可独立使用：

- `/health`
- 核心 CRUD/API
- 错误码
- 响应格式
- 数据持久化

### L3 Gateway 对接测试

验证前端真实入口：

- `/api/*` 路由代理
- JWT 鉴权
- 权限拦截
- trace_id 透传
- 下游不可用处理

### L4 跨服务集成测试

验证 Sprint 之间真实串联：

- 事件发布/消费
- 依赖服务返回
- 数据状态推进
- 审计和告警联动

### L5 前端交互验收

验证用户在平台中是否能完成业务动作：

- 页面渲染
- 表单校验
- Token 注入和刷新
- 列表/详情/看板展示
- 操作成功和失败提示

## 5. 每个 Sprint 的推进流程

```text
Step 1: 读取原始 Sprint 文档
Step 2: 对照当前代码实现
Step 3: 输出差异分析
Step 4: 确认验收口径
Step 5: 输出前后端对接与测试用例
Step 6: 补齐测试或小范围缺口
Step 7: 执行自动化测试
Step 8: 输出验收报告
Step 9: 进入下一个 Sprint
```

## 6. 处理设计差异的规则

### 应保留的差异

如果差异来自后续 Sprint 的合理演进，并且后续模块依赖它，则保留。

示例：

- 单用户管理员演进为 RBAC。
- APISIX 设想演进为 FastAPI API Gateway。
- 简单审计演进为独立 Audit Center。

### 应修复的差异

如果差异导致当前 Sprint 目标不可用、不可测或前后端无法对接，则修复。

示例：

- 文档要求的核心 API 缺失。
- Gateway 未代理已实现接口。
- 权限码缺失导致平台无法访问。
- 测试无法覆盖关键异常路径。

### 应记录的差异

如果差异暂不影响平台使用，但会影响后续质量，则记录为风险。

示例：

- Docker 构建环境暂不可用。
- 部分事件仅有占位 publisher。
- 外部交易所真实联调尚未执行。

## 7. Sprint 1 起始验收重点

Sprint 1 不应回滚当前 RBAC 和 Gateway 演进，而应确认基础能力稳定：

1. Auth Service 可启动。
2. API Gateway 可启动。
3. 管理员可登录。
4. 登录返回 access token 和 refresh token。
5. `/api/auth/me` 返回当前用户。
6. Gateway 能鉴权并透传用户。
7. 权限模型能兼容 `["*"]` 和细粒度权限。
8. 前端能完成登录、进入主框架、登出。
9. 后端测试覆盖 token、密码、鉴权、权限。
10. 前端测试覆盖登录态、路由守卫、请求拦截器。

每个 Sprint 的最终报告采用以下结论格式：

```text

已通过：
- ...

已修复：
- ...

仍有风险：
- ...

后续跟进：
- ...
```
